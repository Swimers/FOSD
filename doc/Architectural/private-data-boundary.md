# 公开源码与私有数据边界

源码仓库仅保留 `data/QSS` 的样式及其许可证。`data` 中其余内容（模型、点阵、标定、采集记录、设备输入等）留在本地，不进入 Git；旧版大小写不同的 Data 路径也适用。模型坐标文件仍由应用运行时按需导入，不能为了修复缺失输入而重新提交真实数据。

历史清理覆盖全部远端分支中的上述路径、旧 build/Bulid 构建副本，以及原始数据对象在其他路径中的相同内容副本。历史 FOSD 主程序 ZIP 及校验文件也从 Git 移除，避免未经重新审阅的二进制发布包进入公开源码。磁盘上的原始数据和发布文件不删除。

`.gitignore` 在各分支头部加入了相同边界。忽略规则不能阻止 `git add -f`；复制、改名、压缩后的内容也可能绕过路径规则。提交前需要检查暂存文件，不能把此规则或路径扫描当作完整的涉密审查。第三方库、人工编写的算法参数、文档和生成式测试样例的公开许可及保密属性仍需单独审核。

## 发布前检查

```powershell
python tools/check-public-data.py
python tools/check-public-data.py --history
git ls-files data
```

第一项检查暂存索引，第二项检查所有本地可达引用，第三项应只列出 QSS 资源。测试数据应由测试代码生成，或使用经过确认的公开合成数据，不能复制真实设备或模型的数据作为测试样例。

打包脚本可以在被忽略的本地目录产生 ZIP，但二进制不能因源码检查通过就直接发布。重新打包时应另行检查模型、运行配置、采集数据、调试符号和资源内嵌内容。保留的模拟器包不包含审计识别的模型/点阵对象。

## 历史重写后的协作

历史重写会改变提交 ID。协作者应保留自己的未提交工作后，重新克隆清理后的仓库；不要将旧仓库整体合并、推送回来。旧提交号、旧发行记录和基于旧历史的分支不再是公开源码的依据。

强制更新分支只能移除服务器上的可达引用，不能保证 GitHub 立即删除缓存、不可达对象或其他人的克隆。若资料曾公开、存在 fork、PR 缓存或其他副本，需联系相关持有人以及 GitHub 支持处理；仓库管理员确认前继续保持私有。GitHub 自动归档下载不应与本机保留的原始数据或未清理的历史备份一起分发。
