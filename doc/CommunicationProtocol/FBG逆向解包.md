# FBG 传感器数据包协议（基于源码逆向分析）

> **文档性质：** 逆向分析草案，而非设备厂商正式协议规范。  
> **分析依据：** `analyzepackets.cpp`。  
> **范围：** 主数据包（波长/应变）与通道数据包（X/Y 曲线）。  
> **重要说明：** 未提供 `analyzepackets.h`、`global.h`，因此 `MAX_CHANNELS`、`MAX_POINTS`、`DataAddress`、`FLOATA`、`FLOATA2` 的定义尚未得到最终确认。以下将**源码直接确认**与**条件性推断**分开标注。

## 1. 协议总览

### 1.1 两类数据包

程序入口为 `analyzepackets::analyzeData(const QByteArray datagram)`。解析器读取前 4 个字节来确定数据包类型。

| 类型 | 前 4 字节（HEX） | 处理函数 | 功能 |
|---|---|---|---|
| 主数据包（Main Packet） | `FA FB FA FB` | `processMain()` | 解析所有通道的传感器波长，并计算应变 |
| 通道数据包（Channel Packet） | `FA kk FA kk` | `processChannel(k)` | 解析指定通道的 X/Y 曲线采样点 |

通道编号 `kk` 在**当前分发代码**中的有效范围为 `00`～`05`：

| 对应通道 | 包头 |
|---|---|
| CH1 | `FA 00 FA 00` |
| CH2 | `FA 01 FA 01` |
| CH3 | `FA 02 FA 02` |
| CH4 | `FA 03 FA 03` |
| CH5 | `FA 04 FA 04` |
| CH6 | `FA 05 FA 05` |

> 主包代码和注释体现了 **7 个通道** 的设计，但 `analyzeData()` 仅将 `kk < 6` 的通道包交给 `processChannel()`，所以第 7 通道（`kk = 06`）的曲线包在当前代码中不会被解析。

### 1.2 术语与约定

- **偏移（Offset）**：以整个数据包第一个字节为偏移 `0`。
- **`M`**：通道数量，源码表明很可能为 `7`；实际取值由 `MAX_CHANNELS` 决定。
- **`N`**：主数据包中的总传感器数，由一个字节读取。
- **`P`**：通道数据包中的采样点数，由偏移 `6`～`7` 两个字节读取。
- **`D`**：主数据包的数据区起始偏移，即源码中的 `DataAddress`。
- **字节序**：程序按低地址字节先放入联合体的 `u8Byte[0]`，因此在常见的小端宿主机、且联合体成员为相应整数/浮点类型时，相当于小端解码；需要结合联合体定义和目标设备确认。
- **长度**：以下源码中的检查是**最小长度检查**，不是严格的总长度或传输层帧边界约束。

## 2. 主数据包（Main Packet）

### 2.1 主要功能

主数据包用于一次性传输多个通道的 FBG 传感器波长值。接收端根据包头统计各通道传感器的数量，并将后续数据依通道顺序映射至 `CH1_1`、`CH1_2`、`CH2_1` 等传感器编号。后续可据此计算应变、实施初始波长校准或保存为 CSV。

### 2.2 通用二进制结构

```text
字节偏移
0                         4                    4+M           D
|-------------------------|--------------------|-------------|-------------------- ...
| FA FB FA FB             | C1 C2 ... CM       | N / 可选空隙 | S1 S2 ... SN
| 固定包头：4 Bytes        | 各通道数量：M Bytes | 总数等头字段 | 每个传感器 4 Bytes
```

**源码可直接确定：**

- `array[0..3]` 为 `FA FB FA FB`。
- `array[4 + ch]` 为第 `ch + 1` 通道的传感器数量，每个字段占 `1` 字节。
- `array[4 + MAX_CHANNELS]` 为总传感器数 `N`，占 `1` 字节。
- 第 `i` 个传感器数据占 `4` 字节，从 `array[DataAddress + 4*i]` 起读取。

**条件性结构假设：** 若 `MAX_CHANNELS = 7` 且 `DataAddress = 12`，则各字段连续排列，无额外保留字节：

```text
FA FB FA FB | C1 C2 C3 C4 C5 C6 C7 | N | S1(4B) S2(4B) ... SN(4B)
  0..3     |          4..10         |11 |     12 起
```

如果实际 `DataAddress` 大于 `5 + MAX_CHANNELS`，中间可能还存在未解析的保留字段或其他头部信息，不能默认不存在。

### 2.3 字段表

| 字段名称 | 起始偏移 | 字节长度 | 含义 | 确认级别 |
|---|---:|---:|---|---|
| `Header` | 0 | 4 | 固定 `FA FB FA FB` | 确定 |
| `ChannelCount[ch]` | `4 + ch` | 1/通道 | 第 `ch + 1` 通道传感器数量，`ch = 0..M-1` | 确定 |
| `TotalSensors` | `4 + M` | 1 | 总传感器数 `N` | 确定 |
| `Unknown/Padding` | `5 + M` | `D - (5+M)`（若为正） | 可能存在的未解析头部空间 | 待确认 |
| `Sensor[i]` | `D + 4*i` | 4 | 第 `i + 1` 个传感器波长原始值 | 字节位置确定、数值类型待确认 |

若 **`M = 7` 且 `D = 12`**，其具体偏移为：

| 偏移 | 长度 | 字段 |
|---|---:|---|
| `0`～`3` | 4 | `FA FB FA FB` |
| `4`～`10` | 7 | `CH1_COUNT`～`CH7_COUNT` |
| `11` | 1 | `TOTAL_COUNT` |
| `12`～`15` | 4 | `Sensor1` |
| `16`～`19` | 4 | `Sensor2` |
| `12 + 4(N-1)`～`12 + 4N - 1` | 4 | `SensorN` |

### 2.4 数据类型与字节序

源码将每组连续的 4 字节依次写入 `FLOATA2.u8Byte[0..3]`，随后通过 `FLOATA2.all` 取出数值。该值作为波长参与浮点运算，并格式化到小数点后 5 位。

因此，**很可能**采用小端 IEEE 754 `float32`，但 `.all` 的实际声明仍须验证。

例如（**仅在 float32 + 小端的假设下**）：

```text
00 C0 C1 44  ->  1550.0
00 D0 C1 44  ->  1550.5
00 B8 C1 44  ->  1549.75
```

### 2.5 多通道数据排列顺序

各传感器的 4 字节数据**不附带单独的通道标识**；解析器根据各通道数量计算累积偏移，将数据按以下顺序分配：

```text
[CH1 的全部传感器]
[CH2 的全部传感器]
...
[CHM 的全部传感器]
```

设 `C[ch]` 是第 `ch` 通道的传感器数，则其在传感器数组中的开始位置为：

\[
\operatorname{Start}(ch)=\sum_{k=0}^{ch-1}C[k]
\]

例如，`CH1 = 2`、`CH2 = 1`、`CH3 = 3`、其余通道均为 `0`：

| 原始数据序号 | 传感器编号 |
|---:|---|
| `S1` | `CH1_1` |
| `S2` | `CH1_2` |
| `S3` | `CH2_1` |
| `S4` | `CH3_1` |
| `S5` | `CH3_2` |
| `S6` | `CH3_3` |

### 2.6 长度公式

源码规定主数据包需满足：

\[
\boxed{L_{\mathrm{Main,min}}=D+4N}
\]

其中 `D = DataAddress`。

若 `D = 12`，则：

\[
\boxed{L_{\mathrm{Main,min}}=12+4N}
\]

因为 `N` 通过 `quint8` 读取，当前代码表达的单包数量范围为 `0..255`。源码虽然检查 `totalSensors > 1024`，但对单字节的 `N` 而言该条件实际上不可能触发。

### 2.7 主数据包示例

**假设：** `MAX_CHANNELS = 7`、`DataAddress = 12`、传感器值为小端 `float32`。

通道数量为 `CH1=2`、`CH2=1`、其他通道均为 `0`，总数 `N=3`，波长依次为 `1550.0`、`1550.5`、`1549.75`：

```text
FA FB FA FB                    # 4 字节主数据包头
02 01 00 00 00 00 00           # CH1=2, CH2=1, CH3~CH7=0
03                             # 总传感器数 N=3
00 C0 C1 44                    # CH1_1 = 1550.0
00 D0 C1 44                    # CH1_2 = 1550.5
00 B8 C1 44                    # CH2_1 = 1549.75
```

此示例总长为 `12 + 4×3 = 24` 字节，是根据上述条件构造的**示范数据包**，并非从设备实测抓取。

### 2.8 波长校准与应变计算（非协议字段）

软件支持初始波长校准：复位标志启用后，对连续 `20` 次主数据包中的波长值求平均，写入 `data/calibration/初始波长.txt`。

源码的应变计算公式为：

\[
\mathrm{Strain}_i=\frac{0.00075(\lambda_i-\lambda_{0,i})}{A}+B
\]

- `λ_i`：当前解析得到的波长；
- `λ_{0,i}`：校准后的初始波长；
- `A`、`B`：程序中使用的参数，定义不在此文件中。

> 波长、应变字符串、CSV 时间戳均在接收后由软件生成，**不是数据包中的独立字段**。

## 3. 通道数据包（Channel Packet）

### 3.1 主要功能

通道数据包传输某一指定通道的 X/Y 曲线采样值，解析后分别写入：

- `data_x_trans[channel][j]`：第 `j` 个 X 值；
- `data_y_trans[channel][j]`：第 `j` 个 Y 值。

### 3.2 二进制结构

```text
0      1      2      3       4      5       6      7      8           708
|------|------|------|------|--------------|--------------|------------|-------------- ...
| FA   | kk   | FA   | kk   | UNKNOWN(2B)  | POINTS(2B)   | X区(700B)  | Y区(2×P B)
|------------ 包头 4B --------|              | 低位/高位   | 固定地址区 | Y1,Y2,...,YP
```

**源码直接确认：**

- 偏移 `0..3`：`FA kk FA kk`；
- 偏移 `4..5`：未被当前解析函数读取，意义未知；
- 偏移 `6..7`：数据点数 `P` 的两个低有效字节；
- 偏移 `8 + 2*j`：第 `j + 1` 个 X 数值（2 字节）；
- 偏移 `708 + 2*j`：第 `j + 1` 个 Y 数值（2 字节）。

### 3.3 字段表

| 字段名称 | 字节偏移 | 字节长度 | 含义 | 确认级别 |
|---|---:|---:|---|---|
| `Header0` | 0 | 1 | 固定 `FA` | 确定 |
| `ChannelID0` | 1 | 1 | 通道编号 `kk` | 确定 |
| `Header2` | 2 | 1 | 固定 `FA` | 确定 |
| `ChannelID1` | 3 | 1 | 与偏移 1 相同 | 确定 |
| `Unknown` | `4..5` | 2 | 暂未解析 | 仅位置确定 |
| `PointCount` | `6..7` | 2 | X/Y 采样点数 `P` | 位置确定；数值类型待联合体定义验证 |
| `XDataArea` | `8..707` | 700 | X 数据固定起始区域，X 值每个占 2 字节 | 确定 |
| `YDataArea` | `708..(707+2P)` | `2P` | Y 数据，Y 值每个占 2 字节 | 确定 |

### 3.4 X/Y 数值编码

解析器使用 `FLOATA` 联合体，把每个数值的 2 个数据字节放入 `u8Byte[0]`、`u8Byte[1]`，并将后 2 字节设置为 `0`。

在**小端且 `FLOATA.all` 为整数**的假设下，使用 16 位无符号数解码：

\[
X_j=b_{8+2j}+256\cdot b_{9+2j}
\]

\[
Y_j=b_{708+2j}+256\cdot b_{709+2j}
\]

其中 `j = 0..P-1`，`b_k` 为偏移 `k` 处的无符号字节值。

**注意：** 2 字节的实际含义仍取决于 `FLOATA.all` 类型，暂不可绝对确定其为 `uint16`；从代码的两字节赋值方式看，它较可能是非负整数采样值。源码没有给出 X/Y 的物理单位或比例系数。

### 3.5 为什么 Y 数据从偏移 708 开始

X 数据从 `8` 开始，Y 数据从 `708` 开始，二者固定起始地址的间距为：

\[
708-8=700\ \text{Bytes}=350\times2\ \text{Bytes}
\]

这表明协议**可能**为 X 轴预留了最多 `350` 个双字节采样点的固定区域。

- **`P < 350`**：读取前 `P` 个 X 值；其余 X 区字节在当前解析器中被忽略，不能确定它们是否为零或填充。
- **`P = 350`**：X 数据恰好占满 `8..707`，Y 数据紧随其后。
- **`P > 350`**：当前解析逻辑会在固定 Y 起始地址附近发生 X/Y 区域重叠；是否允许此点数，需查看 `MAX_POINTS` 及设备协议。

### 3.6 长度公式

源码分别计算：

```cpp
requiredXBytes = 8 + P * 2;
requiredYBytes = 708 + P * 2;
requiredBytes  = max(requiredXBytes, requiredYBytes);
```

由于 `requiredYBytes` 始终较大，故：

\[
\boxed{L_{\mathrm{Channel,min}}=708+2P}
\]

| 采样点数 `P` | 最小数据包长度 |
|---:|---:|
| 100 | 908 字节 |
| 200 | 1108 字节 |
| 300 | 1308 字节 |
| 350 | 1408 字节 |

> **1408 字节只是 `P = 350` 时的结果。** 源码未证明所有通道包都固定为 1408 字节。

### 3.7 通道数据包示例

假设发送的是 **CH2** 曲线包（`kk=01`），`P=3`，数值均按小端 `uint16` 表示：

```text
FA 01 FA 01                      # 包头，CH2
00 00                            # 偏移 4..5，未知字段（示意）
03 00                            # 偏移 6..7，P = 3
64 00 C8 00 2C 01                # 偏移 8..13：X = [100, 200, 300]
...                              # 偏移 14..707：未参与当前 3 点解析
0A 00 14 00 1E 00                # 偏移 708..713：Y = [10, 20, 30]
```

该示意包最小长度为 `708 + 2×3 = 714` 字节。省略号不是实际字节；构造真实字节流时，应将其替换为准确数量的占位字节。

## 4. 两类数据包对照

| 项目 | 主数据包 | 通道数据包 |
|---|---|---|
| 核心用途 | 传感器波长/应变 | X/Y 采样曲线 |
| 包头 | `FA FB FA FB` | `FA kk FA kk` |
| 通道定位 | 通过各通道数量隐式定位 | 包头直接指定通道 `kk` |
| 点数 | 1 字节总传感器数 `N` | 偏移 6..7 的 2 字节点数 `P` |
| 数据元素长度 | 每传感器 4 字节 | 每个 X/Y 值 2 字节 |
| 数值类型 | 推断小端 `float32` | 推断小端 `uint16` |
| 数据排列 | 传感器按通道顺序连续排列 | X/Y 固定起始地址分区排列 |
| 数据区起点 | `DataAddress`（待确认） | X 从 8，Y 从 708 |
| 最小长度 | `DataAddress + 4N` | `708 + 2P` |
| 后续处理 | 校准、应变计算、CSV 保存 | 曲线数组存储 |

## 5. 逆向实现时的校验建议

在独立实现解包器时，建议至少执行以下校验：

1. **帧头长度：** 接收到的缓冲区至少有 4 字节。
2. **帧头分流：** 先判断 `FA FB FA FB`，再判断 `FA kk FA kk`（`kk=00..05`）。
3. **主包字段长度：** 读取总数前，应确认缓冲区包含偏移 `4 + MAX_CHANNELS`；再校验 `len >= DataAddress + 4N`。
4. **主包通道计数：** 检查 `sum(ChannelCount[ch]) == TotalSensors`；这一项是**建议新增的校验**，原解析器未执行。
5. **通道包字段长度：** 至少 8 字节才可读取点数；再校验 `0 <= P <= MAX_POINTS` 且 `len >= 708 + 2P`。
6. **X/Y 区域约束：** 若设备采用互不重叠的 X/Y 区域，应进一步检查 `P <= 350`；原代码没有直接写这一限制。
7. **数值转换：** 在获得联合体真实定义之前，不应将 `float32` 和 `uint16` 作为已完全验证的协议常量。
8. **帧边界与检错：** 此文件未实现 CRC、校验和、包尾或黏包拆包逻辑；这**不代表传输协议本身一定不存在**这些机制，可能在其他模块完成。

## 6. 源码中的未决问题

| 事项 | 现有证据 | 待确认内容 |
|---|---|---|
| 主包通道数 | 主包循环和注释体现 7 通道 | `MAX_CHANNELS` 的实际定义 |
| 曲线包通道数 | `analyzeData()` 仅允许 `channel < 6` | 是否应支持第 7 通道 |
| 主包数据起点 | 由 `DataAddress` 指定 | `DataAddress` 的数值及可能存在的附加头字段 |
| 主包数值类型 | `FLOATA2` 组装 4 字节并用于波长计算 | `.all` 是否为 IEEE 754 `float` |
| 曲线数值类型 | `FLOATA` 组装 2 字节并清零高字节 | `.all` 的整数宽度、有无符号及字节序 |
| 曲线最大点数 | 存在 `MAX_POINTS` 校验 | 允许的上限是否为 350 |
| 通道包偏移 4..5 | 代码未读取 | 是否为状态、长度或保留字段 |
| 包尾 / CRC | 当前函数没有校验 | 是否由传输层或其他代码处理 |
| 总数一致性 | 代码分别读取通道数和总数 | 设备发送时是否保证 `ΣCi=N` |

## 7. 最简协议速查表

### 主数据包（条件性实例：`MAX_CHANNELS=7`、`DataAddress=12`）

```text
FA FB FA FB | C1 C2 C3 C4 C5 C6 C7 | N | FLOAT32_LE[N]
4 B        | 7 B                  | 1 B | 4N B

最小长度：12 + 4N 字节
```

### 通道数据包（偏移布局直接来自源码）

```text
FA kk FA kk | UNKNOWN(2 B) | P(2 B) | X(从偏移8起,每点2B) | Y(从偏移708起,每点2B)

最小长度：708 + 2P 字节
k：00..05
```
