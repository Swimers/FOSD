# Classic 后续迁移与功能裁剪计划

日期：2026-11-03。状态：规划，尚未实施。

## 结论与范围

后续工作收敛为：**16 通道 JCS 协议、TCP 双角色通信接口、均值置零与 JSON 配置、独立业务运行控制、波长绘图及图片保存、Windows 中文路径支持，以及未实现旧功能的全层清理。** 其余行为以新版本为准，不再以恢复旧版全部功能为目标。

本计划按用户对 A01–A24 的最新取舍制定，替代[原审计报告](../MigrationAudit-2026-11-03/README.md)中的迁移建议；原报告保留为源码事实和问题来源，不再作为实施范围。仅针对 `apps/FOSD-Classic-QWidgets`、`ui/FOSD-Classic-QWidgets` 及其所需共享后端修改，不安排 FOSD-Win 或 Linux 开发。本次交付是新报告，不代表其中的代码删除或迁移已经执行。

范围解释：

- A18 的“完全一处”按“完全移除账号相关前后端”执行规划。
- A04 的偏移量指波长/应变标定使用的偏置（如 B）；A06 删除的是旧二维观察坐标的 X/Y/Z 原点平移，两者不混用。
- 已有功能与旧版行为不同的，保留新版有效实现及必要控件；未实现且本次未明确要求实现的旧功能，删除其控件、路由、Presenter/Backend 残留和相关资源。不会因“存在差异”就删除正常工作的新版功能。
- “保留接口”是可调用且返回明确不支持状态的扩展接口，不保留可点击却无实现的操作入口，也不保留只有声明、调用会链接失败的接口。

## 工作包与接口安排

### W1：16 通道协议与 TCP 通信（P0）

修改 [JCSWavelengthParser.cpp](../../src/protocol/JCSWavelengthParser.cpp)、[PacketDecoders.cpp](../../src/communication/PacketDecoders.cpp) 及对应头文件、测试和发送样例。以旧 `pocketsconfig.h` 与 `analyzepackets::processMain()` 的真实布局为标准：

| 字节偏移 | 含义 |
| --- | --- |
| 0–3 | `FA FB FA FB` |
| 4–19 | 16 个通道各自的传感器数量 |
| 20 | 总传感器数，按旧版单字节字段读取 |
| 21–23 | 保留字节，不擅自解释或要求为零 |
| 24 起 | 按通道顺序排列的 little-endian float32 波长，每项 4 字节 |

最小有效长度为 `24 + 4 * totalSensors`，通道计数之和应与总数一致；总数必须符合其单字节表示范围。校验头、长度、计数与记录边界。有效波长校验在协议/采样层统一约定，避免无效值进入基线。UDP 数据报应与旧版允许尾部填充的约定一致；TCP 按明确的帧长拆包，不能把任意额外字节当作填充吞掉下一帧。保留 MP 独立协议，不把 MP 的布局改成 JCS。

移除 7 通道回退、相关样例和“格式尚待确认”的旧说明。协议布局常量集中定义，Decoder 和 Parser 共享，避免再次出现前层拒收、后层可解析的矛盾。

TCP 复用现有 [Tcp.cpp](../../src/communication/Tcp.cpp) 的双角色接口，两种角色共享同一套字节流拆包器与协议解析器，不复制 ClientParser/ServerParser。补齐连接关闭/替换时拆包缓存清理，禁止上一连接半帧串入下一连接。当前单客户端策略沿用新版；不增加多客户端广播或设备控制协议。

Classic 通信页提供角色选择、Client 目标地址/端口、Server 本地地址/端口、打开/关闭或监听/停止、收发区、清空和状态/错误显示。TCP 仅作通用通信助手；收到有效支持协议帧可进入既有数据链，不要求解调仪专用握手。原始文本/字节可以收发，未识别内容不能显示为成功解包；保持手动发送现有字节语义，不隐式补 CRLF。

验收：16 通道首末数据正确；7 通道旧方案不再作为独立格式受支持；错误计数、截断、异常长度可报告；模拟 Client→Server 与 Server←Client 均能完成 JCS/MP 的单帧、分片、多帧、断线重连测试。当前没有 TCP 硬件，不把模拟通过描述成设备通信已验证。

### W2：均值置零与统一 JSON 配置（A03 P0，A05 P1）

优先接入 A03 必需的 JSON 读写接口，再完成统一业务配置覆盖；不让 P0 基线功能先使用临时文本格式，后续再重写。撰写时工作区已存在 [IConfigStore.h](../../src/config/IConfigStore.h)、[JsonConfigStore.h](../../src/config/JsonConfigStore.h) 及其实现，提供统一读写、分区、锁与原子写入，见[现有配置模块说明](../Architectural/config-integration.md)。后续应复用 `fosd_config`，核验其测试并补 Classic Runtime 的业务接线，不重复新增文件读写层。当前模块没有主动接入业务配置，不能据此认为 A03/A05 的业务闭环已完成。

建议在应用配置适配层补 `ConfigurationTypes` 定义结构与 schemaVersion、`ConfigurationCodec` 负责 JSON 转换与业务字段校验；文件操作继续委托已有 `IConfigStore/JsonConfigStore`。统一返回业务错误及有效配置，不向前端暴露底层可变对象。现有局部读写接口可继续保留，应用一组有关联的基线/标定参数时须先验证完整对象再提交，不靠隐式合并残缺字段覆盖当前有效状态。

首版字段范围：

| 分组 | 内容 | 不保存的内容 |
| --- | --- | --- |
| 元信息分区 | schemaVersion、明确的协议格式标识 | 7 通道兼容开关 |
| 基线 | 采样数量、各 `(channel,sensor)` 身份与基线均值、采样时间和来源标识 | 单帧临时缓存、未完成采样和过期回执 |
| 标定/解算输入 | 当前 A/B、calibrationFactor、传感器顺序、通道标定系数 | 旧 axis 坐标平移；不新增算法参数体系 |
| 波长显示 | 可见通道集合及本次实现所需显示设置 | 把通道勾选转换成解算输入过滤 |
| 通信 | 串口/UDP/TCP 的有效连接参数与 TCP 角色 | 开机自动连接、连接中状态和活跃 socket |

以上为建议结构，实施时固定 schema 与默认值并提供样例。沿用现有“根对象按模块分区、每个顶层值为对象”的契约，版本号放入元信息对象，不在根层添加标量而破坏现有格式。配置内容以新版参数和校验规则为准，不安排旧 INI/TXT/JSON 的自动迁移。未支持字段（如阈值、旧保存周期、axis、账户）不进入新 schema；现有模型/场景业务不因统一配置模块而扩展成全量场景工程保存。

读取需校验类型、必需字段、有限数值、协议布局、基线数量及传感器身份一致性、映射索引和重复项策略；未知 schemaVersion 拒绝应用并给出原因，损坏配置保留当前有效状态。成功解析不等于已应用：由 Runtime 向计算模块提交配置，收到 revision 回执后才更新“已生效”状态。沿用现有 UTF-8 JSON、文件锁和 QSaveFile 原子替换机制，失败保留原文件并回显错误。

均值置零建议默认采样数 **20 帧**，使用置零请求之后到达的有效完整帧；每个 source revision 只计一次，不对 UI 定时器反复读取到的同一帧重复计数，不使用显示过滤后的数据。采样全程保持来源、16 通道布局和传感器身份/顺序一致；断线、来源切换、布局变化或超时导致本次失败，旧有效基线保持不变。有效数据不足时不提交部分均值。采样数和超时参数应有确定默认值及有效范围。

状态流程：`空闲 → 采样中(k/N) → 校验中 → 提交中 → 已生效 → 已保存`。支持失败/取消返回，重复点击不启动并行采样。采样累加不依赖绘图历史，不改变当前响应策略。提交前复核当前连接/配置代次，旧请求晚到回执不能覆盖新请求；写入失败必须显示“已生效但未保存”，不得伪报全部完成。读取基线同样经过校验与配置回执；有基线不代表自动启动通信、解算或渲染。

验收：20 个已知有效帧的均值正确、重复 revision 不计数、异常值/断线/布局变化不污染旧基线、状态与提交回执一致；保存后重启读取恢复；非法 JSON/版本、文件失败不破坏原文件或有效会话。本项验证统计、配置和调用状态，不扩展为 IFE 算法精度验证。

### W3：三业务运行控制（A21 P1）

在应用服务层统一提供通信、解算、动态显示命令与只读状态，通过后端回执更新控件。通信操作只由通信页发出；增加独立解算启停接口及控件；三维 Start/Pause/Stop/Reset 仅操作 VTK 动态显示状态和显示形状。禁止三维按钮间接启停采集或计算。

| 业务 | 状态/前提 | 操作后的预期 |
| --- | --- | --- |
| 通信 | Closed/Opening/Ready/Listening/Connected，保留通道原有状态 | 开关不隐式启动解算/动态显示；关闭只停止该通道输入 |
| 解算 | Stopped/Running，另区分等待有效帧、缺配置及异常 | Start 需有效配置；无输入显示等待；硬件标定输出不强制要求 STL，位移结果需模型；Stop 停止新帧派生计算，不关闭通信 |
| VTK 动态显示 | Stopped/Running/Paused，另区分等待结果/无模型 | Start 需模型，可等待有效结果；Pause 冻结当前动态帧；Stop 停止动态帧更新；Reset 恢复原始形状并保持停止状态。均不影响通信/计算 |

建议界面分别使用“开始/停止解算”“开始/暂停/停止动态显示”等明确名称。动态显示停止不应让相机、网格或模型加载等现有交互失效。暂停渲染时不再让未显示的新结果更新三维帧相关的选点位移/最大位移标签，保证同一三维画面与其数据一致；独立硬件表和波长页面仍按自身状态更新。

联合规则：

- 通信断开后解算保持用户启用意图但标注“等待数据”，不得把旧帧不断当作新结果；所有通道关闭不自动清空用户配置。重新接入后先校验来源和布局，再按现有设置恢复处理。
- 停止解算时保留最近有效快照并标注其状态；已经排队的结果需以运行代次/revision 判断是否可接收。再次开始不能接回上次运行的过期结果。
- 解算运行时切换配置/模型，沿用已有版本确认机制；三维等待新版本结果，不能用旧模型结果覆盖新模型。清理模型后保持通信及允许的硬件标定业务，动态显示转为无模型状态。
- 原始波长存储仍按当前通信数据链运行；停止解算不等于停止整个存储会话，派生应变/位移不再产生新记录。三维暂停不影响当前存储。保留新版连续与单次保存策略，不新增定时采样模式。

接口组织可增加 CalculationControl 的运行命令和对应回执、VisualizationControl 的动态更新开关，以及 Runtime 的聚合状态；不以销毁/重建线程模拟暂停，不改既有线程划分和轮询频率。验收覆盖三维暂停而计算仍更新、停止计算而通信仍收包、通信断线与恢复、配置提交期间连点、模型卸载及退出排空。只验证生命周期和调用链，不安排 IFE 数值比对。

### W4：波长显示、绘图与图片保存（A04 P1，A17 P2）

重写通信页波长显示业务：完整帧进入显示模型，表格按 `(channel,sensor)` 标识数据，通道选择仅投影到表格和曲线。沿用新版提交式筛选交互并保存显示配置；未选通道仍参与基线、标定、应变/位移以及当前原始保存链路。

本计划将用户明确要求的“波长显示绘图”落在 **JCSWavelengthParser 发布的波长记录** 上，建议横轴时间、纵轴 nm、每个有效传感器独立曲线，CH1–16 决定可见曲线集合。旧 `processChannel()` 的采样点 X/Y 频谱与波长帧不是同一种数据，本轮不据 A17 自动恢复已退役的 JCSChannelParser 频谱链；旧窗的绘图、通道显隐及图片保存交互可复用，原“频谱”标签应按实际内容改为“波长曲线”。

复用 QCustomPlot 和现有约 10Hz 界面刷新策略。曲线缓存使用明确的固定窗口/容量，不因本次功能实现无限增长；这是绘图基本边界处理，不开展全链路性能优化或逐帧无损展示改造。没有数据、通道取消、重新连接及传感器身份变化均有确定行为，禁止将同名但不同来源传感器直接拼成一条连续曲线。

图片保存操作由 Presenter 选择路径，View/绘图适配层导出当前可见曲线、坐标轴和图例，返回明确成功/失败；首版支持 PNG，JPEG/BMP 按旧导出能力一并接入。保存的是当前图像，不改变 CSV/SQLite 记录策略；A04 筛选不因此影响原始文件记录。零可见通道或无数据时给出空图状态并禁止误报已保存有效曲线。

验收：逐个筛选 CH1/8/16、全选/全不选、改变筛选前后对比解算输入与原始保存不变；波长表/曲线一致；图片可打开且内容与当前视图一致；中文路径、取消和写入失败处理正确。

### W5：旧功能与全层残留清理（P1/P2，随各工作包完成）

删除应覆盖 `.ui` 控件/布局、View 声明与 relay 信号、Presenter 本地跳转与 prepareRequest、Backend 支持范围、Runtime 分支、PanelId/FeatureId、面板工厂/注册、资源及 CMake 列表、测试和文档。不能只隐藏控件、保持一整条 unavailable 调用链，或把测试改成继续期待“尚未实现”。
