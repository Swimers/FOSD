## 2. 显示状态与边界

2026-09-28 在板上运行 `wayland-info`，外接 HKC V2718M 显示器对应的输出为 **1920×1080、60 Hz、`normal`**；HDMI-A-2 已连接，位置为 `(0, 0)`。DSI-1 也处于连接状态，Weston 另有一个 1080×1920 输出，位置为 `(1920, 0)`。本次配置并未关闭 DSI-1，也没有旋转 FOSD 的 UI；改变的是 HDMI 输出模式、主输出选择和镜像设置。


## 4. 恢复原板端启动配置

需要恢复原厂 UI 时，先停止 FOSD，移走它的启动脚本，再把原厂脚本放回启动目录：

```sh
/etc/init.d/S51fosd stop
mv /etc/init.d/S51fosd /etc/init.d/disabled/S51fosd
mv /etc/init.d/disabled/S50systemui /etc/init.d/S50systemui
```

需要同时恢复此前的 Weston 显示配置时，使用板上保留的备份，随后重启：

```sh
cp /etc/xdg/weston/weston.ini.bak /etc/xdg/weston/weston.ini
cp /etc/profile.d/weston.sh.backup-20260928-133757 /etc/profile.d/weston.sh
sync
reboot
```

上述恢复命令不会删除 FOSD 程序、VTK 库或 `data/`。要重新启用 FOSD 自启动，可把 `/etc/init.d/disabled/S51fosd` 移回 `/etc/init.d/S51fosd`；若板上副本不存在，再从本仓库的 [`scripts/rk3588/S51fosd`](../scripts/rk3588/S51fosd) 部署。

## 5. VTK 页面闪退修复（2026-09-28）

切换到含 `QVTKOpenGLNativeWidget` 的页面时，调试器抓到 `SIGSEGV`：`QVTKOpenGLNativeWidget::paintGL()` → `vtkOpenGLRenderer::Clear()` → 地址 `0x0`。运行时 VTK 共享库均已加载，因此该故障不是缺失 `.so`。交叉编译缓存确认 VTK 8.2 使用 `VTK_OPENGL_USE_GLES=ON`、`OPENGL_ES_VERSION=3.0`，但其内置 GLEW 将 GLES 核心函数 `glClearDepthf` 按可选扩展加载；崩溃时函数指针为空。

已将 [`vtk-8.2-glew-gles.patch`](../scripts/rk3588/vtk-8.2-glew-gles.patch) 应用到虚拟机的 `~/Desktop/VTK/VTK-8.2.0/Rendering/OpenGL2/vtkOpenGLRenderWindow.cxx`，使 GLES 构建在 `glewInit()` 前启用 `glewExperimental`。随后交叉编译并安装 VTK Release 到 `~/Desktop/FOSD/lib/VTK/VTK-Linux-release`。板上仅替换了：

```text
/root/Qt_Project/Qt_Test_Compilation/lib/VTK/libvtkRenderingOpenGL2-8.2.so.1
```

板上原文件保留为同目录的 `libvtkRenderingOpenGL2-8.2.so.1.pre-glew-fix`。新文件 SHA-256 为 `a442ce5449a65881d1ff1a4a211ba6d2f08e529abd6c75b3d8e5bcecc3fd0f2e`。修复后进入 VTK 页面，用户确认显示正常；调试器读取到 `glClearDepthf` 和 `glDepthRangef` 函数指针均为非零，FOSD 进程继续运行。另补齐了上述两张三维背景纹理；这些图片缺失与本次段错误无关。

## 6. 三维关键点编号黑框修复（2026-09-28）
