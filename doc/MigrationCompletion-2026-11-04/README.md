## 使用方式

配置路径由 `config::ParameterStore::runtimePath()` 决定：默认在可执行文件目录 `config/parameters.ini`，也可用 `FOSD_CONFIG_FILE` 指定。默认模板 `core-defaults.ini` 保持只读用途。有效计算配置会由计算模块按现有 INI 机制校验保存，启动时恢复；不会因为恢复配置自动打开通信。

额外分区：

```ini
[classic.baseline]
sampleCount=20
timeoutMs=10000
; identity 由采样成功后记录，不建议手工修改

[classic.display]
; channels 由界面通道选择操作保存
```

`sampleCount` 有效范围1～10000，`timeoutMs` 有效范围100～3600000；无效值拒绝启动置零。手动读取配置后仍通过计算配置回执确认生效。通信的三种传输参数继续使用已有类型化配置分区，保持其现有校验与保存接口。

操作顺序：在通信页选择传输和参数→打开通道→接收有效波长→置零并等待采样及配置确认→载入 STL→控制三维动态显示。解算可单独停止/启动；重新置零后如因布局变化停止了解算，需要主动启动。连续/单次数据保存和曲线图片保存是不同操作；保留新版 CSV/SQLite 格式与发送字节语义。

## 验证范围

使用当前源码重新构建 Classic Release，执行全部16个 CTest 目标。验证内容包括：

| 层次 | 本轮证据 |
| --- | --- |
| 协议与拆包 | 原解析测试更新为16通道，覆盖首/末通道、无传感器、255总数、错误计数/截断、特殊float位模式；Decoder 测试覆盖TCP不同切分与连包 |
| TCP 双角色 | Runtime 测试创建真实本机 QTcpServer/QTcpSocket；两种角色均发送第16通道 JCS 波长，验证半帧不发布、补齐与连包产生正确完整帧 |
| 基线/配置/控制 | Runtime 测试以不同波长的20帧核对均值及 INI 恢复；勾选通道不改变基线；停止解算时新输入不产生结果，再启动后恢复；单次波长CSV可写 |
| Classic 整体 | 从真实 Classic 控件打开UDP、接收16通道包、点击置零、读取回执、加载中文STL路径、获得 HYY 结果；暂停渲染后新解算仍产生而显示位置冻结；点击导图/保存按钮生成可读取PNG及非空CSV；截图检查渲染宿主与裁剪结果 |
| 保留后端 | 通信、MP协议、INI配置与参数、计算调用链、CSV/SQLite、端到端、可视化、关键点生命周期和场景测试继续运行 |
| 裁剪 | UI测试检查保留面板/新增控制存在、被裁剪控件不存在；Classic组合测试检查Plate/追踪入口及底部状态栏不可见 |
